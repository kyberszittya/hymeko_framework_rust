# Editor: fold attribute leaf-decls onto a node's HUD (with values)

**Date:** 2026-06-21 · **Author:** Aiko (Claude Code) for Dr. Csaba Hajdu
**Plan:** [docs/plans/2026-06-21-editor-attribute-hud/](../docs/plans/2026-06-21-editor-attribute-hud/)

## Summary
Compiling a robot yields ~122 decls but only ~6 are structural links — the rest are imported vocabulary
leaves (`effort`, `box`, `AXIS_X`, `type`, `length`…) and per-instance scalar leaves (`mass`, `origin`,
`dimension`). The Hypergraph 3D view drew every one as a sphere. Per the chosen **full** option, leaf
"attribute" decls are now **folded out of the sphere set and shown with their values on the owner node's
HUD** (hover/click) via a default-on **"Attributes: HUD"** toggle. This spanned Rust → WASM → JS because the
snapshot did not previously carry field values.

## What changed (all non-core)
- **`hymeko_formats/src/snapshot.rs`** — `NodeDto.value: Option<String>` (`#[serde(default)]`, additive) +
  `render_value(&ValueR, …)` (Str → `"…"`, Num → int-trimmed, List → `[a, b]`, Ref → target name);
  populated from `decl.anno.value`. `ValueR` is only *read/matched* (it lives in core `hymeko_core`) — no
  core edit.
- **WASM rebuild** — `wasm-pack build --target web --release --out-dir ../docs/editor/pkg` (tools.yaml,
  §1-approved 2026-06-12); `hymeko_wasm` forwards `snapshot_json` unchanged. Build finished in 47 s.
- **`docs/editor/views/adapters.js`** — `value` threaded into vertex objects; new pure
  `foldAttributes(nVertices, hyperedges, scopeSegs, vertices) → {isAttr, attrsOf}`.
- **`docs/editor/views/hypergraph3d.js`** — "Attributes: HUD/nodes" toggle (default HUD); attribute
  vertices hidden in `computeFilter`; `infoFor` shows the node's own value + its folded children as
  `name = value`; the stats line counts the hidden leaves.
- **Cache-bust** — `adapters.js?v=28`, `hypergraph3d.js?v=26` (all importers: editor.js, kinematic.js).

### Classification (the contract)
A node is an **attribute** iff it (a) is not a hyperedge member, (b) is a scope leaf, and (c) has a scope
parent — exactly the scalar config leaves. It folds onto its immediate parent (a non-leaf, so still drawn).
A member, container, or root is **never** an attribute, so a pure-hyperedge graph (the `strategy.hymeko`
bundle-of-bundles) or a flat vertex set (the combinatorial graphs) is returned unchanged — nothing hidden.

## Test results
- **Rust:** `snapshot_nodes_carry_rendered_field_values` — `mass`→`1.5`, `tag_str`→`"hello"`,
  `vec`→`[1, 0, 2]` all serialize (verifies `decl.anno.value` is populated, so the HUD is not a silent
  no-op); the existing relationships test still passes. **2/2.** `cargo clippy -p hymeko_formats` clean.
- **JS:** full editor suite `node --test docs/editor/views/*.test.mjs` — **78 passed** (3 new
  `foldAttributes` tests: folds leaves onto owner; members/containers/roots never fold; flat/pure-hyperedge
  folds nothing).
- **Coverage:** the Rust renderer, the JS classifier branches, and the value-population path each have a
  test. Not automated: the live in-browser HUD render (no headless WASM-in-browser path) — verified
  structurally at every layer instead.

## Performance / static
Pure `O(|V|+|scope|)` JS fold; one short string per node in the snapshot. No render-loop cost change.
`rustfmt --check` on `snapshot.rs` shows only **pre-existing** double-blank-line diffs (lines 16, 113) that
predate this change; my additions are fmt-clean and I left the unrelated whitespace untouched
(minimal-diff discipline).

## §6.5 anti-patterns
None. `foldAttributes` is one pure function (no per-kind wrappers); the toggle is parametric, not a forked
view; the classifier reuses the existing scope-relationship data rather than recomputing containment.

## Open issues / follow-ups
1. **Vocabulary containers still render** (`axes`, `units`, `geometry`, `AXIS_X`…) — they are non-leaves, so
   the fold keeps them; the existing per-namespace "Show:" filter hides the whole `meta_*` namespace if
   wanted. A deeper "collapse a container into its parent's HUD" mode could go further if you want it.
2. **HUD scroll** — a node with many attributes makes a tall tooltip; a max-height/scroll on `.view3d-tip`
   would help for the densest links.
3. **Live browser confirmation** — the one unautomated check; the Rust value test + JS fold tests cover the
   logic end to end.
