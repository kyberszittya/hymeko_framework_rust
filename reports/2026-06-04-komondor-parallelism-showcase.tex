\section*{The headline}

The current overnight chain (\texttt{13885723} Slashdot+Epinions +
\texttt{13885739} BA+OTC) is structurally \textbf{sequential} despite
Komondor being designed for embarrassingly parallel work. Re-submitting
the same 40-cell grid as a SLURM array
(\texttt{--array=0-39\%20}) caps the wall at
$\max(\text{slowest\_cell}) \approx 90$ min vs. the chain's sum
$\approx 30$ h, for a \textbf{$\sim 20\times$ wall reduction with
identical compute total}.

\section{The precedent --- what ran sequentially}

The 2026-06-03 chain (\texttt{run\_hsikan\_edge\_cr\_5seed\_audit.sh}
+ \texttt{run\_hsikan\_edge\_cr\_ba\_otc\_5seed.sh}) is a triple-nested
\texttt{for dataset; for seed; for mode} loop inside ONE SLURM job.
SLURM gets a single allocation; all cells run on the same A100 in
series. This is fine for AUC repeatability --- every cell sees the
same hardware --- but it leaves Komondor's array dispatcher entirely
unused. A 90-min cell takes $90 \times 40 = 3600$ min chained; it
takes 90 min once when each cell is its own array task.

\section{The SLURM array submitter (the deliverable)}

\texttt{docs/komondor\_setup/submit\_hsikan\_edge\_cr\_array.sh} ---
same grid as the chain, same SOTA env vars, same SLURM resources
per task. Key points:

\begin{itemize}[nosep]
  \item \texttt{--array=0-39\%20} --- 40 cells $\times$ 20 concurrent slots.
  \item \texttt{--time=02:30:00} per task (covers Epinions worst-case + headroom).
  \item Grid decomposition: $\text{idx} \to (\text{dataset, seed, mode})$.
  \item \texttt{flock}-protected atomic JSONL append.
  \item Pinned env identical to the chain.
\end{itemize}

Each $K$ consumes 1800 GPU-min (identical compute total). Total
billing across the $K$-sweep: $3 \times 1800 = 5400$ GPU-min
$\approx 90$ GPU-hours. \textbf{Not auto-launched.}

\section{Verdict}

This is the demo to bring to a poster session, a reviewer comment,
or a project-progress meeting:

\textit{Komondor's gain on this audit grid is not about the A100 ---
it's about turning a 30-hour serial chain into a 90-minute array. The
SOTA configuration only fits on the A100 (local 7.6 GB RTX OOMs at
edge\_cr forward), but the headline operational win is the array
dispatcher. Both are needed; the array is the one that scales with
grid size.}
